Upgrade the module to Go 1.27 and switch JSON handling to the new `encoding/json/v2` package where it makes sense.

### What didn't work

## Step 2: Verify json/v2, bump go.mod, and migrate the two call sites

**Author:** go127

### Prompt Context

**Verbatim prompt:** "upgrade to Go 1.27 and adopt encoding/json/v2 at the single JSON call site." Bump `go.mod`'s `go` directive from 1.26 to 1.27, switch `/jobs/email.go` and `/jobs/email_test.go` from `encoding/json` to `encoding/json/v2`, but only if v2 compiles under Go 1.27 without `GOEXPERIMENT=jsonv2` — otherwise do the version bump only and report back. Run `make test` and `go vet ./...`; leave everything uncommitted for review.
**Interpretation:** Do the version bump unconditionally, but treat the v2 adoption as conditional on a real compile check, not on go1.27's release notes or memory of jsonv2's history.
**Inferred intent:** Take the toolchain upgrade and a well-scoped, low-risk API adoption, while guarding against silently depending on an experimental flag that CI or other developer machines might not have set.

### What I did

Confirmed `go1.27.0` was already installed (`go version` → `go1.27.0 darwin/arm64`) and checked `go env GOEXPERIMENT`, which came back empty — no experiment flags active in this environment. Before touching the real module, I built a throwaway scratch module (`/private/tmp/.../scratchpad/jsonv2test`, not part of this repo) with `go 1.27` in its `go.mod` and a `main.go` that imports `encoding/json/v2` and calls `json.Unmarshal`. It compiled and ran cleanly with no `GOEXPERIMENT` set, printing the unmarshaled struct. That settled requirement 3: v2 is unconditionally available in Go 1.27.

With that confirmed, I bumped the real `go.mod` with `go mod edit -go=1.27` (then `go mod tidy`, which changed nothing else — no dependency versions moved). Then I changed the import in `/jobs/email.go` (the `json.Unmarshal` call inside `SendEmail`) and in `/jobs/email_test.go` (the `marshalJobData` test helper's `json.Marshal` call) from `"encoding/json"` to `"encoding/json/v2"`. Ran `gofmt -l ./jobs/` (silent, so formatting was already fine) and `go build ./...` to confirm the switch compiles in the real module, not just the scratch one.

Ran the full suite with `make test`: it brought up the `versitygw-test` Docker container, ran `go test -tags sqlite_fts5,sqlite_math_functions -coverprofile cover.out -shuffle on ./...`, and every package passed, including `app/jobs` at 84.0% coverage (unchanged from before — same tests, just running against v2 now). `go vet ./...` came back clean. Grepped the whole repo for `"encoding/json"` afterward and found zero remaining hits, confirming these were genuinely the only two call sites, matching Step 1's survey.

Self-reviewed by dispatching two independent `general-purpose` sub-agents (per the code-review skill) to review the diff, the `model.SendEmailJobData` struct, and every place that struct is constructed or consumed repo-wide, plus the required comment-leakage and single-use-constant checks. Both came back clean.

### Why

The task explicitly gated v2 adoption on a real compile check rather than trusting general knowledge of `encoding/json/v2`'s history (it shipped behind `GOEXPERIMENT=jsonv2` in earlier Go versions), so verifying in isolation first — before editing the real module — avoided leaving the repo in a broken state if the flag turned out to still be required.

### What worked

Building a tiny throwaway module in the scratchpad directory to test v2 in isolation was fast and conclusive — no ambiguity about whether some other setting in the real `go.mod` or environment was masking a `GOEXPERIMENT` requirement.

### What didn't work

Nothing failed. The whole change compiled, vetted, and tested clean on the first attempt; no test needed adjusting for v2's stricter semantics because `model.SendEmailJobData` has no json tags, no case-only field collisions, and no custom `MarshalJSON`/`UnmarshalJSON` on its fields (`model.EmailAddress` is a plain string-kinded type, `Keywords` is `map[string]string`).

### What I learned

`encoding/json/v2` is genuinely unconditional in Go 1.27 — no `GOEXPERIMENT=jsonv2` needed, confirmed both in a scratch module and in the real one. Also, per one reviewer's incidental finding: there's currently no production code path anywhere in the repo that actually constructs and enqueues a `SendEmailJobData` job (only `jobs/register.go` registers the `SendEmail` handler, and only the test helper marshals the struct) — that's a pre-existing gap unrelated to this change, not something this diff introduced or is responsible for fixing.

### What was tricky

Nothing was tricky in the end — the biggest risk (a hidden `GOEXPERIMENT` dependency) was ruled out early with a five-minute isolated test, which made the rest of the change mechanical.

Nothing else changed — `go mod tidy` made no further edits to `go.mod` or `go.sum`.
